# 超级小云 · Grok Supercloud

帮助用户用一句「保活 + 任务 + 截止时间」保持 Grok Bot 云电脑活跃。只在 Grok Bot 云电脑上使用；它依赖 Grok 的**前台 Shell 工具调用等待**。后台进程、定时器或本脚本单独运行不能保证主机不休眠。模型和接力仍可能消耗额度，不承诺 24 小时稳定或零 token。

## 启动对话

用户只说「保活」或没有指定截止时间时，先简短提示：短任务建议写任务和结束时间；需要全天可写「24小时」；未知结束时间先给一个上限，到期可再次启动。询问缺少的任务、截止时间以及是否执行已有命令；不要替用户猜时间或自动创建无限期任务。时间应解释为用户当前时区；确认具体日期、时间和时区在有歧义时，不将过去时间悄悄变成未来。未来开始时间不由脚本安排，到时才启动。

## 启动

将 `S` 设为本技能的 `scripts` 目录。用户只要求保活已有会话或云电脑时，不运行其他命令：

```sh
"$S/ka-start" --task '任务描述' --until '24h'
```

截止时间支持 `90m`、`24h`、带时区的 ISO 8601；`HH:MM` 是电脑本地时区的下一个该时刻，涉及日期或不同时区时优先传带时区的 ISO 8601。已有明确 PID 的任务可加 `--pid PID`；仅用户明确要求启动具体命令时才用 `--run '命令' --cwd '目录'`。脚本会启动命令并记录退出状态及本地日志，绝不推测命令。没有 PID 或命令时这是按期限保活，不会假装能检测任务是否完成。

启动结果是一行 JSON：`START` 表示需要一个 watcher，`JOIN` 表示已有有效租约，登记完成，不再启动 watcher。`START` 返回 `lease`；把它和脚本绝对路径、截止时间交给**一个**低推理强度后台子 Agent。`JOIN` 仅表示租约未过期，不能证明等待者仍在运行；异常退出的租约最多约 15 分钟后失效。不要输出 lease。若已过租约仍未接力，重新登记任务或请用户检查后启动；不要自行无限重试。

## Watcher

子 Agent 必须使用 Grok 的前台 Shell 工具调用，调用一次：

```sh
"$S/ka-wait" --lease '<lease>'
```

允许 Shell 前台阻塞约 12 分钟（例如 `block_until_ms: 760000`，按当前工具实际允许值设置）。**不要以后台 Shell、`nohup` 或 `block_until_ms: 0` 替代前台等待**，否则不能证明云电脑保持活跃。命令每轮只输出一个状态词：

- `WAIT`：仍有任务且期限未到，立即再次前台调用。
- `DONE` / `EXPIRED`：结束监视；调用一次 `ka-report`，向用户简述结果和日志末尾（只针对明确启动的命令；谨慎处理日志中的敏感信息）。
- `BUSY`：已有等待者；退出，不要再启动第二个。
- `STALE` / `ERROR`：停止并告知主会话，不要循环重试。

后台子 Agent 可能有时长限制；每棒最多 3 次 `ka-wait`，仍为 `WAIT` 时向主会话返回一行 `RELAY`，主会话立即用**同一个 lease**接力下一棒。单次前台等待和后台任务的具体上限由当前平台决定；遇到拒绝或超时应报告，不能保证持续 24 小时。

## 查看和停止

`"$S/ka-report"` 查看状态和最多 8 行本地日志。`"$S/ka-stop"` 停止所有保活，`--job ID` 停止指定登记。**停止保活或到期不会杀掉用户任务进程**；如需中止任务，应另按用户明确要求处理。任务状态 `ended` 只表示被跟踪进程已退出，不能证明成功；`expired` 表示到期，任务可能仍在运行。
